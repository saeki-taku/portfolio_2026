# 春の夕方・夜・就寝後レイヤー受け入れ準備

2026-10-11時点。新しい分離素材は未受領。以下は実装済み表示と、素材受領後に確認する契約であり、夕方・夜のレイヤー実装完了を意味しない。

## 現在の表示経路

- `src/pages/index.astro` のPC昼は採用済みの描き直し凛と外景・室内・カップの合成。SP昼はv21 manifest順の9層。両方とも保持する。
- PC夕方は `pc-spring-evening-clear-v1/scene-reference.png`、起きている夜と就寝後は `pc-spring-night-clear-v1/` の各完成画像を表示中。これらは過去の確認用一枚絵で、今回の確定分離素材ではない。
- SP夕方・夜・就寝後の専用表示は未実装。どの時間帯もSP昼v21へ戻している。開発パネルも未対応と明示する。
- 時刻境界は `src/lib/scene-time.ts` に集中している。東京時刻で昼06:00、夕方17:00、起きている夜19:00、就寝後23:00。これを変更しない。
- 表示の切り替えは `src/lib/scene-display.ts` のPC専用処理、開発用手動選択は `src/components/SceneSettings.astro`、通常の自動選択は `src/pages/index.astro` にある。SPの時間帯別素材を受領したら、両経路が同じ対応表を使うよう接続する。素材未対応時のSP昼フォールバックは対応素材が揃うまで維持する。
- HTMLロゴとナビは画像の外側。夜のロゴ文字色指定はPCに限らず新しいSP夜でも可読性を確認する。

## 各素材セットの受領条件

順序は夕方PC/SP、起きている夜PC/SP、就寝後PC/SP。各セットを独立した版付きフォルダとして受け取り、まず README と manifest を読む。原本や旧試作を上書きしない。

1. PCは現在の1345×1170、SPは1024×1997の共通キャンバスを基準とし、全層が各セット内で同寸法・同じ左上原点・透明余白を保持すること。別座標の人物素材なら、座標変換または配置値をmanifestに明示すること。
2. manifestに下から上への正確な重ね順、各層の役割、人物・人物由来の影や補完層の連動グループ、カップや植物など前景との前後関係、完成・人物なしの比較プレビューを記すこと。就寝後は人物グループを含めず、人物・影・ノートの残像がない完成プレビューを用意すること。
3. 夜の外景は時間帯に対応した実画素で制作すること。特に就寝後は建物の窓明かりを大幅に減らし、街灯など最低限の光だけを残す。CSSの一律暗色フィルターを消灯素材の代用にしない。
4. 顔・髪・手・服・姿勢、窓枠、窓台、植物、カップ周辺を合成した参照画像と比較できること。接触影の位置と人物非表示時の影の消去を素材側で成立させ、CSSの追加影で不一致を隠さない。
5. 画像内にロゴ・ナビ・操作UIを描き込まないこと。素材の制作上の補完箇所と既知の不一致を README に記すこと。

## 受領後の実装・検証

- 原本の寸法、透過、重ね順とプレビューを検査し、ソースを変更せず版付き `src/assets/validation/` に複製する。まず時間帯ごとに一つの共通親要素へ同寸法で積み、既存のPC/SP画角と等比拡縮する。
- 通常表示と開発用の手動選択でPC/SPそれぞれのシーンが一致すること、時刻境界と開いたページの自動更新が働くことを確認する。実装が終わった時間帯だけ暫定一枚絵と昼フォールバックを置き換える。
- 人物と人物由来の影・補完層を一緒に切り替え、人物なし参照と比較する。カップと植物の独立性も確認する。就寝後は凛がいないことと街の消灯を確認する。
- 複数のPC/SP画面比率でスクリーンショットを撮り、構図・窓枠・窓台・前景の重なり・夜のロゴ可読性・ナビを確認する。`npm run check`、`npm run build`、開発用ビルドとローカル検証を行う。
